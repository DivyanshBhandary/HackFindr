# Measured impact: timed before-and-after test

Goal: one honest number for the slides, like *"finding an event you can join went from 18 minutes to 1 minute,
and from 6 websites to 1"*. Run it with **5–10 students** who have not used HackFindr before.

## The task (same for both rounds)

> Find **3 events** (hackathons or workshops) that **you are eligible for**, that are **online or within 300 km**
> of your city, and whose **registration closes in the next 14 days**.

## Round A: the usual way (before)

- Any websites or apps they like (Google, Unstop, Devfolio, Instagram…). HackFindr is not allowed.
- Start a timer when they start and stop it when they have 3 events written down.
- Count the **websites or apps** they opened.
- Afterwards, check each event: is it really open to them, in range and closing within 14 days?
  Count the **mistakes**.

## Round B: with HackFindr (after)

- Sign in, fill in year, branch and skills (time this separately; it only happens once).
- Same task, same timer. They can use the city box, the radius, the **I can join** chip and **Closing soon**.
- Count websites (should be 1) and mistakes the same way.

To make it fair, let half the students do round B first. Use a different city for each round, or give a
5-minute gap, so they don't simply remember events.

## What to report

- Use the **median** times, not the average (one slow person shouldn't skew it).
- "Median time to find 3 events you can join: **A min → B min** (n = 5)."
- "Websites opened: **A → 1**. Wrong picks (ineligible or closed): **A → B**."
- Note honestly what HackFindr cannot do yet (e.g. events from sources it doesn't fetch).
